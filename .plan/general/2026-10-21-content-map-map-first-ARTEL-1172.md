# 2026-10-21 — 화면 지도 빌드 화면을 지도 중심으로 다시 짠다 (ARTEL-1172)

- Date: 2026-10-21
- GitHub Issue: None (Jira ARTEL-1172)
- Status: Implemented (draft PR) — 씬 순번은 orche ARTEL-1173

## Goal

`/projects/:p/content-map?build=:id` 를 지도(씬 · 화면 그래프)가 화면의 중심이 되게 다시 짠다. 있던 기능은 하나도
빼지 않는다 — 아래 목록이 체크리스트이고, 칸마다 새 자리를 적는다.

## Non-goals

- 그래프 라이브러리 도입(Konva · Fabric · React Flow) — 문제는 모양이지 그리는 엔진이 아니다.
- 스캔 · TC 생성 진행도(도넛) · 취소 · 서버 쪽 중복 스캔 거절 — SDK · 서버를 함께 고쳐야 해서 따로 간다.
- 서버 변경은 씬 순번 두 칸(`buildOrder` · `entry`, ARTEL-1173)뿐이다. 없으면 예전 순서로 그린다.

## 지금 화면의 기능 목록 → 새 자리

### 주소 · agent

| 기능 | 새 자리 |
|---|---|
| `?build=` 읽기, 기본 빌드면 `replace` 로 주소 고침, 고르면 history 한 칸 | 그대로 |
| 옛 주소 `/game-builds/:b/content-map` → `?build=` redirect | 그대로 |
| agent field `contentMap.build` (빌드 select) | 그대로 — target 이 새 빌드 버튼 |
| agent action `contentMap.scan` · `contentMap.scanAndGenerateTestCases` (버튼 target · blocked 문구 같음) | 그대로 — 버튼이 근거 패널 안에 남는다 |
| agent action `contentMap.overwriteTestCases` (보이는 버튼 없음, highlight 는 TC 생성 버튼) | 그대로 |
| 빌드 바꾸면 선택 · 확대 · 스캔 상태 초기화(`key`) | 그대로 |

### 머리 · 배너

| 기능 | 새 자리 |

| 섹션 제목 `화면 지도` + InfoHint, 빌드 select, 빌드 없음 빈 상태 | 제목은 작업공간 머리 하나(섹션 h2 는 화면 낭독기용). 빌드 select 는 찾기 · 최신 · 보는 중 · 라벨 · 등록 시각이 붙은 빌드 버튼 + 목록 |
| 페이지 H1 `콘텐츠 맵` + InfoHint(증거 문서를 서버가 읽은 결과) | 제목은 하나로(`화면 지도`). H1 의 InfoHint 문구는 머리 메타 줄의 InfoHint 로 |

| `← 빌드 목록으로` (실제로는 `/qa` 로 감) | 빌드 상세(`game-builds?build=`)로 가게 바로잡는다 |

### 근거(스캔) 패널 — `EvidenceScanPanel`

| 기능 | 새 자리 |
|---|---|
| 스캔할 게임 select(연결된 것만, 끊기면 첫 것으로), 근거 다시 스캔, 스캔하고 TC 생성(`carryOver`) | 근거 줄에 늘 보인다(agent action target). 빠르게 눌러도 한 건만 나가고, 게임이 스캔하는 동안은 꺼진다 |
| 확인 시각 줄, 막힌 사유 네 가지, 요청함 · 실패(`aria-live`) | 막힌 사유 · 요청함 · 실패는 근거 줄 아래, 확인 시각은 `자세히` 펼침 안. 지도가 아직 없거나 안 읽혔으면 처음부터 펼친다 |
| SSE 스캔 상태(점 · 이름 · 게임 · 경과 초 · 오류 · TC 결과 다섯 가지 · 케이스 라이브러리 열기), 서버가 상태 모름 안내 | 펼침 안 그대로. 접혀 있어도 근거 줄에 스캔 상태 한 마디 |
| 실시간 연결 상태 네 가지 | 펼침 안 그대로 + 근거 줄 |
| 적재 막대 `{n}개 중 {m}개 적재`, 실패 수, 밀린 · 실패 문서 목록 | 펼침 안 그대로 + 근거 줄에 `{m}/{n} 적재` |

### 세 칸 — tree · 지도 · 고른 것

| 기능 | 새 자리 |
|---|---|
| tree 전부(키보드 ↑↓←→ Home End Enter Space, roving tabindex, 펼침 동기화, 줄 네 종류와 표식) | 왼쪽 그대로. 씬 줄은 대표 그림 + 씬 색 점 + 이름, 화면 줄은 캡처. 씬은 게임 시작 씬부터 빌드 설정 순서 |
| 지도 클릭 선택 네 종류, 3px 넘게 끌면 클릭 아님, 고른 것과 이어진 것만 또렷 | 그대로. 누르자마자 포인터를 잡아 클릭이 svg 로 새던 결함을 고침(끌기로 판정된 뒤에 잡는다) |
| 씬 상자: 이름 · 화면 수 · 색(scene hue) · 밟음 실선/안 밟음 점선/없는 씬 윤곽 · 대표 이미지 · `아직 관측된 화면 없음` | 씬 카드: 왼쪽 대표 이미지(없으면 자리표시), 오른쪽 이름 + 실행 가능 · 탐색 필요 · 나감 · 들어옴 수, 이미지 아래 화면 수 / 화면 없음. 화면이 6개를 넘으면 앞의 5개와 `+n 화면 더 보기` 칸(그 자리에서 펼침) |
| 화면 노드: 캡처 · 없음/못 불러옴 · 이름 · `{n}회` · discriminator 끝 | 그대로 |
| 씬 전이: 확인 실선 + 속 찬 화살촉 / 미확인 점선 + 속 빈 화살촉, 조건 라벨(14개 넘으면 hover · 선택 때) | 그대로, 선을 상자 옆면에서 가로로 나가게 하고 층을 건너는 선은 상자 위로 돌린다 |
| 화면 전이: 가는 선 + 열린 화살촉, 씬 경계 넘으면 casing, capability 라벨 | 모양은 그대로. 처음엔 고른 것에 닿는 것만 그리고 `화면 전이 n개 모두 보기` 로 켠다. 접힌 화면의 전이는 접기 칸으로 |
| 휠 확대(커서 기준), 끌어 옮기기, `{x}배` · − · + · 전체 보기 | 지도 위 오른쪽 위에 띄움 |
| 전이 없음 · 화면 없음 안내, 없는 씬 목적지 · 이름 감춤 메모 | 지도 위 왼쪽 위에 얹는 한 줄 |
| 범례 여섯 줄 | 지도 아래 접는 한 줄(펼치면 그대로) |
| 고른 것 · 선택 해제 · 더 이상 없음 · 네 종류 상세 전부(화면 · 씬 · 씬 전이 · 화면 전이, 단계 목록 · 조건 트리 · 지식 · capability) | 고르면 오른쪽에서 밀려 들어오는 넓은 서랍(Esc · × 로 닫음). 서랍이 덮지 않은 지도는 그대로 눌러 다른 것을 고른다 |
| 고르면 detail 이 보이게 스크롤(좁을 때) | 서랍이 늘 보이는 자리에 떠서 필요 없어짐(좁으면 화면 전체 서랍) |

## Approach

- 높이 · 폭: 작업공간 본문부터 세 칸까지 flex 로 이어 창 높이를 채운다(600px 아래만 스크롤). 섹션 폭 상한은 이 화면만
  2400px. 세 번째 칸을 없애고 상세는 오른쪽 서랍으로, 지도가 그 폭을 쓴다.
- 그림 모양(`contentMap.css`): 상자 채움은 표면색, 테두리는 기본 테두리색, 씬 색은 이름 앞 점 하나. 확인 · 미확인의 두
  채널(실선/점선, 속 찬/빈 화살촉)은 그대로, 미확인 amber 는 덜 굵게.
- 선 경로(`screenMapLayout.ts`): 옆 열은 상자 옆면에서 가로 접선 cubic, 열을 둘 이상 건너면 위 · 아래 통로로 돈다. 한
  옆면에 닿는 선은 상대 끝 높이 순으로 고르게 나눈 자리(port)로.
- 순서: 서버가 주는 `entry` · `buildOrder` 로 씬을 줄 세워, 순환 그래프의 출발점 · 열 안 순서 · tree 순서가 다 따른다.
- 스크롤 칸(tree · 서랍 · 빌드 목록)은 `EdgeScrollbar`, 서버 문장 속 백틱은 코드 칩.
