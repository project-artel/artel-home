# 케이스 라이브러리가 화면 폭을 쓰고, 케이스를 문장으로 편집한다

- Jira: ARTEL-872
- 브랜치: `refactor/home-대시보드-케이스-라이브러리가-저작-팔레트와-다른-화면처럼-보인다-ARTEL-872`

## 무엇이 문제였나

같은 프로젝트의 같은 TestCase 를 보는 화면이 둘인데 생김새도 조작법도 달랐고, 그 위에
대시보드 쪽은 넓은 화면을 거의 쓰지 못하고 있었다.

2560px 화면에서 재 본 값이다.

| 구간 | 폭 |
| --- | --- |
| 왼쪽 nav | 216px |
| **버려짐** | **569px** |
| 목록 | 840px |
| 편집 | 340px |
| **버려짐** | **583px** |

nav 를 뺀 2344px 중 내용이 쓰는 것은 1192px 이고, **1152px — 가용 폭의 49%** 가 좌우
여백으로 사라졌다. 원인은 `.section-content` 의 `width: min(100%, 1240px)` 이고
워크스페이스의 모든 화면에 걸려 있다. 게다가 비율이 거꾸로였다 — 훑는 목록이 840px,
오래 들여다보는 편집이 340px.

## 패턴을 먼저 찾았다

기억이 아니라 근거로 골랐다.

- [TestRail](https://www.testrail.com/platform/) 이 이 도메인의 표준으로 내세우는 것이
  **three-pane view** 다.
- [Material 3 canonical layouts](https://m3.material.io/foundations/layout/canonical-examples/overview)
  는 확장 폭에서 list-detail 두 패널을 동시에 두고, 초대형 창에서는 side sheet 를 세 번째
  패널로 쓰라고 적는다.

세 안을 실제 데이터·실제 비율로 그려 비교한 뒤 **전폭 표 + side sheet** 를 골랐다. 88건을
훑으며 비교하는 일에 가장 강하고, 폭이 곧 정보가 되기 때문이다. 치른 값도 적어 둔다 —
바로 앞 커밋에서 저작 팔레트와 맞췄던 행 모양을 표로 다시 갈랐다. 씬 칩 필터와 키보드
탐색은 여전히 두 화면이 같은 컴포넌트를 쓴다.

## 무엇을 했나

**폭.** `.section-content` 의 폭 제한을 이 화면에서만 푼다. `:has(.kg-section)` 이 같은
이유로 이미 1440px 로 넓혀 둔 선례를 따랐다. 제목(`.section-header`)은 형제라 `:has` 를
부모에 걸어 같이 풀었다 — 내용만 넓히면 제목이 옛 1240px 자리에 남아 화면 가운데에 뜬다.

**라벨.** 범주값은 글자 대신 라벨로 낸다. 화면은 `SceneChip`, 명세 등급은 `SpecGradeChip`,
결과는 상태 점을 단 pill. 표에서는 열 머리가 이미 "명세 등급" 이라고 말하므로 칩의
`명세 상태:` 접두는 `bare` 로 뗐다.

**편집.** 사전조건 → 내용 → 기대결과는 순서가 있는 하나의 문장인데, 똑같이 생긴 textarea
셋을 쌓으면 같은 무게로 보인다. 번호와 잇는 실로 순서를 되돌렸다. 화면은 이미 쓰고 있는
이름을 칩으로 내주고, 결과는 값이 셋뿐이라 드롭다운 대신 셋을 다 보인다.

## 대비를 재서 고친 것

공유 CSS 로 옮기면서 팔레트에 있던 미달이 대시보드로 따라왔다. 원인이 셋 다 같다 —
강조색을 그 색으로 물들인 배경 위에 **글자로** 얹으면 무너진다. 색은 점·테두리·띠가 들고
글자는 본문색으로 되돌렸다.

| 대상 | 전 (라이트/다크) | 후 |
| --- | --- | --- |
| 행 부제 | 4.11 / 3.91 | 5.00 / 5.10 |
| 안 고른 필터 칩 | 2.84 / 4.35 | 15.20 / 14.70 |
| 고른 필터 칩 | 2.84 / 4.35 | 12.28 / 11.56 |
| 결과 pill | **1.59** / 4.35 | 12.28 / 11.56 |
| 고른 행의 스텝 | 2.84 / 4.35 | 12.28 / 11.56 |

## 확인한 것

- 표가 전폭을 쓰는 것과 잘린 셀이 0 인 것을 `getBoundingClientRect` 로 셌다
- 행 여섯 칸의 `top` 과 높이가 하나로 모이고 hover 배경이 한 색인 것을 확인했다
- 시트 열기 · `Escape` 닫기 · 초점이 첫 입력칸으로 가는 것을 실제 이벤트로 확인했다
- `＋N` 팝업은 이 프로젝트 씬이 7개뿐이라 안 뜨므로, 상수를 잠깐 3 으로 낮춰 열어 확인했다
- 대비는 라이트·다크 양쪽에서 열두 곳을 재서 미달 0

## 안 한 것

- 다른 워크스페이스 화면의 폭 제한은 그대로 뒀다. 함께 푸는 것은 따로 정할 일이다.
- 저작 팔레트는 조회 전용 그대로다. 거기에 편집을 넣지 않았다.
- `TestCaseLibrary.tsx` 와 `testCaseLibrary.ts` 의 대소문자 충돌은 이 작업이 아니다.
